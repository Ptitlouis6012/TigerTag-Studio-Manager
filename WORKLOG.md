# Worklog — v2.31.1 (in progress)

## Added
- Local MCP server for AI assistants (read-only) — full reference `docs/MCP.md`. Turned on **per profile** in *My profile › AI assistants* (off by default; the server runs only while the signed-in account opted in, stops on sign-out or a switch to a profile that did not): a toggle with an ⓘ bubble, then three tiles with the apps' logos (Simple Icons SVGs in `assets/svg/brands/`) — **Claude** (Studio builds a `.mcpb` bundle, MCPB manifest 0.3, URL + token baked in, and opens it → Claude Desktop's install dialog), **Cursor** / **VS Code** (their MCP install links) — plus a *Renew the key* button (new `icon-key`; hold 1.5 s to confirm, hover bubble saying what it breaks — `setupHoldToConfirm` hint extended with an optional `data-hold-tip` lead sentence; once renewed the key turns into a green tick and the button pops for 1.8 s — no message, nothing moves); the tiles and the button stay visible but greyed and inert while the toggle is off (Claude Code, a developer tool, is documented in `docs/MCP.md`, not offered in the UI). 14 tools: `data_guide` (the notice: every field — data1-data7, id_*, tiers — and collection), `account_overview`, `search_inventory`, `get_spool` (own temps, else the material's recommendation), `inventory_summary`, `list_racks`, `list_printers` (model names, online state), `list_friends`, `friend_inventory`, `list_wishlists`, `data_history`, `list_devices`, and raw `firestore_get` / `firestore_query` over the account's own tree + what friends share + public profiles. Every document is returned DECODED next to its raw fields (labels resolved by ID; the seven chip data slots read per product type — filament temps / diameter, resin mixing / work / curing / washing, unused for accessories and spare parts; info1-3 as refill / recycled / filled flags); counts per physical spool (twins de-duplicated). Security: 127.0.0.1:5795 only, bearer token, Host check against DNS rebinding, browser Origins refused, `secrets` / `apiKeys` refused, credentials (passwords, access / check codes, tokens, keys, certs, cloud logins) and the e-mail / Google real name masked — `services/mcpServer.js`, `services/mcpStdioBridge.js`, `main.js`, `preload.js`, `renderer/inventory.{js,html}`, `docs/MCP.md`, `CLAUDE.md`, `renderer/CODEMAP.md`, `CODEMAP-main.md`, `ROADMAP.md`

## Changed
- Printer board (grid view): zoom held between 50 % and 100 % (buttons, typed value and wheel all go through one clamp; a stored zoom outside the range is brought back in on load). The storage and camera plans keep their own 30–200 % range — `renderer/inventory.js` (`PRINTER_ZOOM_MIN/MAX`, `_clampPrinterZoom`)
- Product photos in the cart (order view), the favorites / order lists and wishlist rows are framed in the product's colour like the grid cards — the cart had no frame at all, and wishlists drew a flat border that could not show a bi / tri-colour. The frame is now the product's real swatch (`colorBg` of its material snapshot, gradients included) painted under a transparent border; a photo that fails to load falls back to that swatch, and while photos are held (scrolling, colour filter) the tile stays a full colour swatch instead of vanishing — `renderer/inventory.js` (`_productThumbHTML`), `renderer/css/70-detail-misc.css`

## Fixed
- Grid cards: the identical-spools count badge was a 23×20 oval for a single digit; it is now a perfect 22 px circle for one digit and a pill from two (border-box, min-width = height), and the number itself is centred to within half a pixel, measured: it sits in its own block trimmed to cap-height → baseline (`.group-card-count-n`, `text-box: trim-both cap alphabetic`; the font's extra room above figures left it 0.6 px low, and `text-box` does nothing on the flex badge itself), with proportional figures (tabular ones put a lone "1" ~1.2 px off) — `renderer/css/70-detail-misc.css`, `renderer/inventory.js`
- The TD badge on grid cards (and on small thumbnails) was unreadable in light mode — the themed ink went dark-on-dark on the dark scrim. It sits on a photo whose colours the theme cannot know, so its colours are now fixed: dark frosted pill, white text, hairline ring — `renderer/css/70-detail-misc.css`
- Printer board (grid view): a newly added printer no longer queues at the left edge below everything (every addition went further down one column, out of sight) nor piles up in the top-left corner. Unplaced machines are laid out FIRST, then their widgets under them (in page order a widget could be placed before its brand-new card and stack under a card that was not anywhere yet); a new machine takes the first free place in reading order big enough for its card AND its widget column (`planFreeSlot`); objects still waiting for a spot no longer count as obstacles at (0, 0) (`planFreeSpot`). After each layout, `_planSettleColumns` pushes down whatever a grown widget now covers (the units box gains rows when CFS / AMS data arrives), carrying on down the column so the fix never makes a new pile — only downward, never an object in the user's hand; two overlapping CARDS are left alone (may be deliberate) — `renderer/inventory.js`
- The main window now reopens where and how the user left it — size, position, maximized, full screen — instead of a fixed 1280×820 every launch. Saved to `<userData>/window-state.json` on move / resize (debounced) and on close (normal bounds kept while maximized); restored only if it still lands on a connected display (an unplugged monitor no longer opens the app off-screen); maximize / full screen applied at reveal so the hidden splash-gated window is not shown early. First launch (nothing saved) opens maximized — `main.js`
