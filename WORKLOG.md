# Worklog — v2.21.2 (in progress)

## Added
- **A connected machine's filament storage is shown as its UNITS** — one named block per physical object (Ext., AMS 1, AMS 2…) in the widget beside its card, rather than one flat strip: an X1C with two AMS and a spool arm is three boxes standing in three places, and thirteen squares in a line said none of that. **The storage itself is stored on the machine**, as a `units` map on its own document — one entry per physical unit: an AMS, CFS or ACE box, a holder pair, the external arm. A map rather than an array so one unit can be written without rewriting its neighbours, and on the document rather than in a subcollection because the units are few, are always read with the machine, and would otherwise be invisible to anyone reading the printer document. Each carries its shape, a user-renamable label, a position on *each* board, and its slots: what the user assigned (`uids`) and what the machine last reported, stamped with `seenAt` so a reader knows how old it is. Every brand now describes its units, not just a flat slot list, from its own `PROTOCOL.md`. The seeder never overwrites what the user owns — label, shape, both positions and assignments — and a unit that stops being reported is marked absent rather than deleted, because unplugging an Elegoo's Canvas hub must not discard what was in it. The agreed vocabulary and shape: `docs/printer-storage-terms.md` — `renderer/inventory.js`, `renderer/printers/*/index.js`, `docs/printer-storage-terms.md`, `docs/firestore-schema.md`, `llms.txt`
- Groundwork for assigning an inventory spool to a machine slot: one resolver (`renderer/printers/filament.js`) turns a TigerTag spool into the values any of the six brands can be told — Bambu's catalogue id and tray type, Creality's id and pressure, the family/fill split, the vendor token, the temperatures, and each brand's own colour format. Written from the mobile app's proven behaviour, not from its code. Never refuses: an unknown brand or material becomes a Generic stand-in in the right colour at the right temperature, and the result flags whether the identity is exact. Internal — no user-facing change yet — `renderer/printers/filament.js`
- A connected machine's feed slots are their own movable object on the printer board, next to the machine rather than stuck under its card — placed, snapped and selected like anything else there. The board itself now keys everything off one `data-board-id` instead of assuming one object per machine, which is what the AMS racks will plug into. The widget shows the same coloured squares the machine's own panel draws, each carrying its material family (PLA, ABS, PETG…), at exactly a rack slot's size and scale in picture view (64 × 64, 6 px apart) — a machine's bay and a shelf's bay hold the same object, so a spool must not appear to change size when it moves between them — in balanced rows of at most five, the widget sizing itself to its bays. An unknown bay reads `?`, a bay with a colour but no declared material reads `—`. Hovering one names the bay, the filament's brand and its variant (*E1 — R3D · PLA Basic*); an empty bay is drawn as an outline rather than skipped, so the strip never shortens when a spool runs out. Each brand now normalises its own wire format — AMS trays, CFS materials, ACE slots, tool-changer nozzles — behind one `getSlots` on the brand registry, so the slots can be read anywhere instead of only inside each brand's own filament card — `renderer/inventory.js`, `renderer/printers/*/index.js`, `renderer/css/40-printers.css`
- A move handle on every card, left of the ⋮, on both boards. Outside Arrange it is the only thing that moves a machine or a rack — the rest of a printer card opens its panel, and a rack no longer slides because you reached past its title — while in Arrange the whole card stays a handle. New `icon_move` glyph — `renderer/inventory.js`, `renderer/css/30-racks.css`, `renderer/css/40-printers.css`, `renderer/css/70-detail-misc.css`, `assets/svg/icons/icon_move.svg`
- Rubber-band selection on both boards — sweep the empty board to select several machines (Printers) or racks (Storage, in Arrange mode only), shift to add to the selection, then drag any selected card to move the whole group at its existing offsets. One shared implementation (`wirePlanMarquee`) so the two boards cannot drift apart — `renderer/inventory.js`, `renderer/css/30-racks.css`, `renderer/css/40-printers.css`

## Changed
- A printer card is a switch: clicking the machine whose panel is already open closes it, instead of leaving the ✕ as the only way back — `renderer/inventory.js`
- Panning both boards is now the wheel button only; the left button on empty board draws a selection instead — `renderer/inventory.js`
- Several racks can be selected at once, where it used to be one (Arrange mode, as before — outside it a press on the board still belongs to the racks and their slots) — `renderer/inventory.js`, `renderer/css/30-racks.css`
- In a group move, each carried card answers for its own landing spot, so the red overlap edge names the machine or rack actually sitting on something. Still a warning — a drop is never refused — `renderer/inventory.js`
- **The printer view is a board now, like Storage.** It used to split into "Connected" and "Offline" sections, so a machine losing its link changed place — you lost track of it at the moment you were looking for it, and a card you had put somewhere never stayed put. One flat list: the state is already a coloured dot on the card and did not also need to be a change of address. Each machine is then placed by hand, on a permanent grid, with the storage plan's own magnetism and guides — the geometry and the panning were made board-agnostic rather than duplicated, so one implementation serves both. Wheel to zoom, middle-drag to pan, buttons and a typed value from 30 % up, and the point under the cursor is held still so zooming can never be mistaken for something having moved. The board carries its own zoom (`tigertag.printer.planZoom`), since the two plans hold different things at different scales. The position lives on the printer as `plan: {x, y, z}`, so it follows the account; a machine never placed flows below the arrangement instead of landing on top of it, and the one moved last sits in front. **The whole of the old organisation went with it**: the sort drag-and-drop that rewrote `sortIndex` behind the arrangement, the state partition and its section headers, the full grid rebuild that fired whenever a machine blinked — a connect or a disconnect now touches one dot, because nothing about a card's position depends on its state any more — the grip that only ever existed for the sort drag, and the trailing "+ add a printer" card, which had no place on a board and duplicated the "+" in the search bar. The whole card is the handle now: a click still opens the panel, and the move begins after 4 px of travel. `sortIndex` survives as the order of the table view. — `renderer/inventory.js`, `renderer/css/40-printers.css`



## Fixed
- Grabbing a card on either board now rings it in the accent colour. The only sign of a grab used to be a drop shadow, which on a dark board under a card that has barely moved is no sign at all — a grab that took and one that missed looked the same. The three states are written as one ordered block per board (held < selected < colliding) so a collision can never be outranked by a lift — `renderer/css/30-racks.css`, `renderer/css/40-printers.css`
- A card dragged past the edge of its board is now dropped where it last stood, on both boards. The card holds pointer capture, so nothing told it the cursor had left — it kept following a pointer that was no longer over the map, and you had to travel back inside just to let go — `renderer/inventory.js`
- Clicking the ⋮ on a printer card also opened the machine's side panel behind the menu: the press armed an open through the rebuild-safety fallback, which the click handler then never got to cancel — `renderer/inventory.js`
- The closed-hand cursor now appears the moment you press a rack or a machine, instead of after the first pixels of travel, and stays closed wherever the pointer goes during the drag — `renderer/inventory.js`, `renderer/css/30-racks.css`
- Overlap warning on the Storage board is a red outline again, and only that: it used to recolour an outline that Arrange mode alone declared (so nothing showed outside Arrange), and the red wash it painted over the card replaced the drag shadow as well — `renderer/css/30-racks.css`
