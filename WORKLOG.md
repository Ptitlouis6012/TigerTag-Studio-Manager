# Worklog — v2.31.1 (in progress)

## Added
- Local MCP server for AI assistants (read-only) — full reference `docs/MCP.md`. Turned on **per profile** in *My profile › AI assistants* (off by default; the server runs only while the signed-in account opted in, stops on sign-out or a switch to a profile that did not): a toggle with an ⓘ bubble, then three tiles with the apps' logos (Simple Icons SVGs in `assets/svg/brands/`) — **Claude** (Studio builds a `.mcpb` bundle, MCPB manifest 0.3, URL + token baked in, and opens it → Claude Desktop's install dialog), **Cursor** / **VS Code** (their MCP install links) — plus a *Renew the key* button (new `icon-key`; hold 1.5 s to confirm, hover bubble saying what it breaks — `setupHoldToConfirm` hint extended with an optional `data-hold-tip` lead sentence); the tiles and the button stay visible but greyed and inert while the toggle is off (Claude Code, a developer tool, is documented in `docs/MCP.md`, not offered in the UI). 14 tools: `data_guide` (the notice: every field — data1-data7, id_*, tiers — and collection), `account_overview`, `search_inventory`, `get_spool` (own temps, else the material's recommendation), `inventory_summary`, `list_racks`, `list_printers` (model names, online state), `list_friends`, `friend_inventory`, `list_wishlists`, `data_history`, `list_devices`, and raw `firestore_get` / `firestore_query` over the account's own tree + what friends share + public profiles. Every document is returned DECODED next to its raw fields (labels resolved by ID; the seven chip data slots read per product type — filament temps / diameter, resin mixing / work / curing / washing, unused for accessories and spare parts; info1-3 as refill / recycled / filled flags); counts per physical spool (twins de-duplicated). Security: 127.0.0.1:5795 only, bearer token, Host check against DNS rebinding, browser Origins refused, `secrets` / `apiKeys` refused, credentials (passwords, access / check codes, tokens, keys, certs, cloud logins) and the e-mail / Google real name masked — `services/mcpServer.js`, `services/mcpStdioBridge.js`, `main.js`, `preload.js`, `renderer/inventory.{js,html}`, `docs/MCP.md`, `CLAUDE.md`, `renderer/CODEMAP.md`, `CODEMAP-main.md`, `ROADMAP.md`

## Changed
- Product photos in the cart (order view), the favorites / order lists and wishlist rows are framed in the product's colour like the grid cards — the cart had no frame at all, and wishlists drew a flat border that could not show a bi / tri-colour. The frame is now the product's real swatch (`colorBg` of its material snapshot, gradients included) painted under a transparent border; a photo that fails to load falls back to that swatch, and while photos are held (scrolling, colour filter) the tile stays a full colour swatch instead of vanishing — `renderer/inventory.js` (`_productThumbHTML`), `renderer/css/70-detail-misc.css`

## Fixed
- The main window now reopens where and how the user left it — size, position, maximized, full screen — instead of a fixed 1280×820 every launch. Saved to `<userData>/window-state.json` on move / resize (debounced) and on close (normal bounds kept while maximized); restored only if it still lands on a connected display (an unplugged monitor no longer opens the app off-screen); maximize / full screen applied at reveal so the hidden splash-gated window is not shown early. First launch (nothing saved) opens maximized — `main.js`

## Removed
- The "Colour" column of the inventory table (spools and groups), the catalogue table and the favorites table — the photo's colour frame now carries the colour, so the round swatch repeated it. Also removed the now-unused `colorCircleHTML` helper and its table CSS (`td.color-cell`, `.pv-table td.color-cell`, two `.color-circle` overrides; the base `.color-circle` stays for TD1S) — `renderer/inventory.{js,html}`, `renderer/css/70-detail-misc.css`, i18n key
