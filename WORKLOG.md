# Worklog — v2.35.0 (in progress)

## Added
- **Full catalogue data kept on catalogue spools**: a spool created from the catalogue, converted to TigerTag+ or refreshed from the API now stores `catalogProduct` — the local catalogue entry (`id_catalog.json` / synced catalogue) enriched field by field with everything the `product/get` detail adds (description, document links, images, filament block, nozzle / dryer / bed, fan speeds, slicer profiles in `metadata`, brand logo / site, dates…); the chip still gets only the protocol fields. Product cards show the description and, in Details, fan speed, Bambu Studio / Creality Print profiles and the brand site. Documented in `docs/firestore-schema.md`, the backend `README.md` and the AI-assistant data guide — `renderer/inventory.js` (`_catalogFullRecord`, `_productApiFields`, `_refreshApiData`, `normalizeRow`, `_pcDescriptionHTML`, `_pcDetailsHTML`), `renderer/css/70-detail-misc.css`
- **Catalogue product card**: a product opened from the Catalogue views gets its own side card (`#productCardPanel`, catalogue mode) instead of the management card — illustration, identity + chips, no weight bar, "Already N in your inventory" when owned, and four calls to action in a 2 × 2 grid: **+ Inventory** (creates the TigerData+, `_catalogCreate`), **+ Wishlist** (list picker), **+ Cart** and **+ Favorite** (turn into ✓ "In the cart" / "Favorite" once set); a **Product sheet** button sits between the chips and the CTAs and opens the full product card beside it (second press closes it); below come print settings, documents and details. ★ / cart / lists use the very row "+ Inventory" would create (`catalogRow`), so they land on the same product record as the spools; picking another product while the card is open slides the new card in over the old one (same swap as the spool and printer cards) and closes a product sheet left on the old product — `renderer/inventory.js` (`openProductCard`, `_renderProductCard`, `_catViewProductCard`, `_toggleProductCardFlag`), `renderer/css/70-detail-misc.css`
- **Catalogue — nothing found**: when a Catalogue search (or its filters) matches no product, the view says so and offers **Create it by hand**, which opens the Add-product card (TigerData in the cloud or a TigerTag chip) — `renderer/inventory.js` (`_catViewRender` empty state, `[data-cv-create]`), `renderer/css/70-detail-misc.css`
- **Prusa printers (beta)** — every Prusa running PrusaLink (MK4/MK4S, MK3.9/MK3.9S, Core One, XL 1/2/5 tools, MINI/MINI+, MK3S+ / MK2.5S via Raspberry Pi), with or without MMU, with or without a camera. LAN only (Prusa Connect has no public API).
  - Transport in main: `prusa:http` (HTTP Digest auth with a cached challenge, optional `X-Api-Key`, tight path allowlist, GET/PUT/DELETE/HEAD, binary for thumbnails/snapshots) + `prusa:probe` (one unauthenticated `GET /api/version` — 401 Digest "Printer API" / PrusaLink server header / version body) — `main.js`, `preload.js` (`window.prusa`)
  - Driver `renderer/printers/prusa/index.js`: 2 s `/api/v1/status` poll (state map incl. `ATTENTION`, nozzle/bed/chamber temps, progress, time left, fans, speed/flow), `/api/v1/job` on a new job + every 10 s (display name, thumbnail → data URL, G-code metadata), `/api/v1/info` + `/api/version` once (MMU, serial, camera, firmware); reconnect backoff + re-find; auth / old-API / command errors as banners + one toast; debug-mode request log
  - Slots: MMU → 5 bays (one "MMU" board unit), XL → T1…Tn from the model catalog `tools`, else E1; filled from the job's `filament_type` / `extruder_colour` metadata while it runs (PrusaLink reports no loaded filament)
  - Controls: pause / resume / stop on the side card and the printer board (`controlJob`), hold-to-confirm 1.2 s / 1.5 s
  - Camera (`widget_camera.js`): Buddy3D at its own IP over local RTSP (`rtsp://<ip>/live`, ffmpeg → JPEG frames, `prusa:cam-start-rtsp`) or the PrusaLink-side camera (`/api/v1/cameras/snap` every 2 s); one feed per printer for side card, board and in-app camera wall, stopped when no surface shows it (not in the detached camera window yet)
  - Add flow (`add-flow.js`, `probe.js`): network scan (HTTP sweep of the local /24s + shared extra subnets, tickable results) or manual IP (`host[:port]`), then the settings form (PrusaLink password, optional user, optional Buddy3D camera address)
  - Wiring: brand list, picker, model catalog `data/printers/prusa_printer_models.json` (placeholder images), job normalisation, online state, connect/disconnect, camera dispatch, re-find (`refind.js`, ARP MAC) + identity (`identity.js`), AI-assistant data guide brand list — `renderer/inventory.js`, `renderer/inventory.html`, `renderer/css/40-printers.css`, `renderer/printers/prusa/prusa.css`
  - `PROTOCOL.md` for the brand; `ATTENTION` counts as a running job in the shared job bar (`job-bar.js`)
  - Placeholder brand mark `assets/svg/icons/logo_prusa.svg` (a "P", not the official logo) and placeholder model image `assets/img/prusa_printers/no_printer.png` — real artwork to come
  - Marked beta: "Beta" tag next to the brand in the add-printer picker (`meta.beta`), beta notice at the top of its live block
- **Elegoo Centauri Carbon 1 (beta)** — SDCP v3 as a second Elegoo transport (issue #41): `M99999` discovery on UDP 3000 (`elegoo:sdcp-discover` sweep + `elegoo:sdcp-probe`, run in parallel with the CC2's MQTT probe), WebSocket `:3030/websocket` without auth from the renderer (`renderer/printers/elegoo/sdcp.js`): status (Cmd 0 + pushes) → state / progress / layers / time left / temps / fans / speed, attributes (Cmd 1, MAC saved for the IP re-find), camera (Cmd 386 → MJPEG :3031), pause / resume / stop (129 / 131 / 130, hold-to-confirm, not yet confirmed on firmware 1.4.x); every exported entry point of `elegoo/index.js` hands over when `printer.protocol === "sdcp"`. Add flow: CC1 form asks only the IP (`sdcpSchema`, writes `protocol: "sdcp"`); catalog entry "Centauri Carbon (Beta)"; beta notice in its live block; `PROTOCOL.md` §25 — `main.js`, `preload.js`, `renderer/printers/elegoo/{sdcp,index,probe,add-flow,settings}.js`, `data/printers/eleg_printer_models.json`
- Printer settings form can differ per printer within a brand: `schemaFor(printer | prefill)` on the brand + `fixed` values written with the doc; used by the form, the save, the scan multi-select (`scan-pick.js`) and multi-add — `renderer/inventory.js`, `renderer/printers/scan-pick.js`

## Changed
- A newly added spool gets the right empty-spool container (`_containerChoice`, keyed on `brandId` == `id_brand`): not a refill → the brand's only container is set silently, several → the container picker opens narrowed to the brand's ones, none → narrowed to the generic ones; "Without MasterSpool" is never offered there. Refill (`info1`) → the brand's only MasterSpool is set, several → picker narrowed to them, none → picker narrowed to every MasterSpool. The narrowed picker says why and has a "Show all" escape; questions are queued one at a time and only asked for spools added during the session (older spools without a container are filled only when the answer is obvious). Replaces the old auto-assign that fell back to the first generic entry — "Without MasterSpool", 0 g — `renderer/inventory.js` (`_containerChoice`, `autoAssignMissingContainers`, `_queueContainerAsk`, `openContainerPicker(r, { only, hint, onClose })`), `renderer/css/70-detail-misc.css`
- **Favourite MasterSpools**: a ☆ on every MasterSpool in the container picker marks it as a favourite (per account, `favorite: true` on `users/{uid}/containerOverrides/{id}`, beside the weight correction — resetting one keeps the other). Favourites sit in their own group at the top of the picker, and a refill with favourites always asks: the picker is narrowed to the favourites (whatever their brand, listed first) + the brand's own MasterSpools, and is skipped only when that is one single container (the favourite IS the brand's only MasterSpool) — `renderer/inventory.js` (`containerIsFavorite`, `_cpToggleFavorite`, `_renderCpList`, `_containerChoice`), `renderer/css/70-detail-misc.css`, `llms.txt`
- **Container picker filters**: three chips under the search — Cardboard, Plastic, MasterSpool — narrow the list to one kind (press the active chip again to see everything); reset each time the picker opens and combined with the search and a narrowed new-spool list — `renderer/inventory.html`, `renderer/inventory.js` (`_cpSetKind`, `_renderCpList`, `CONTAINER_KIND`), `renderer/css/70-detail-misc.css`
- One product card instead of two (PR #39 by @Ptitlouis6012): "Product info" and "Product card" merged into a single wide card — photo, identity, stock / minimum, buy link / price, print settings, personal links, documents + video, tags, note, details, SKU / EAN; duplicates removed (info button, second ❤/★, read-only price / links / provenance); friend's products keep the read-only card; "In stock: N" follows the inventory live; the illustration (236 px, 20 px colour frame) sits flush in the card's top-left corner like the spool detail card, the actions (+, list, to-order, ★) sit in a row top-right beside the ✕, inside the scrolling body so they scroll away with the content; i18n `reorderPanelTitle`, `reorderOpenProductCard` removed — `renderer/inventory.{js,html}`, `renderer/css/70-detail-misc.css`
  - Laid out after the founder's mockup: hero (illustration, identity, chips, 2-line description) with two figures — **In stock** (dot green / red, "N spools" + minimum) and **Estimated value** (spools × unit price, HT/TTC) —, the buy-link / price pair as two plain buttons, then three tabs kept across re-renders: **Info** (print settings as 2 rows of 3 icon tiles; **Product details** — brand (a link to the brand's site with a small globe when the catalogue knows it), range, material, colour dot, net weight, product id (catalogue link), type, diameter, fan speed — beside **Stock** — minimum ("Not set" when empty, click to edit), current stock, stock value — with **Slicer profiles** (Bambu Studio / Creality Print, only when known) stacked under it; the note with a 0/500 counter; personal links in a dashed zone), **Documents** (documents + video, with an orange count bubble on the tab when there are any, or a playful empty line), **Notes** (tags, SKU / EAN references, raw JSON in debug); the colour(s) as HEX badges on a second chip row beside the illustration. All field ids unchanged, so the existing editors / saves work as before — `renderer/inventory.js` (`_renderReorderPanel`, `_printValues`, `_reorderUpdateStock`, `_reorderTab`), `renderer/css/70-detail-misc.css`
- Elegoo: the Centauri Carbon 2 is named as such everywhere (catalog typo "Centaury" fixed, tutorial label), a Centauri found over MQTT is no longer mistaken for another model, and the empty scan says which models are supported — `data/printers/eleg_printer_models.json`, `renderer/printers/elegoo/{probe.js,tutorial.json}`

## Fixed
- One-time repair of "ghost" product records left by the catalogue-identity bug (a ★ / cart / minimum / note set from a catalogue preview landed on a record no spool matched): on load, a record whose seed names a real catalogue product, that no spool uses, while spools of that product exist under "tt:<id>", is merged into the real record (flags OR-ed, larger minimum, empty fields filled, tags united) and deleted — `renderer/inventory.js` (`_healGhostProducts`)
- Product card opened from the catalogue (or from a product with no live spool) showed "In stock: 0" while the spools existed, and a minimum / ★ set there landed on a different product record: the preview was identified on a "PRODUCT_" row (not chipless → attribute key, plus the tier suffix) instead of as the TigerData+ the catalogue creates ("tt:<id>"). The preview is now built on a chipless id and keyed by `_spoolProductKey`; rows synthesised from a product record carry the record id (`_productHash`) and the stock count / row lookup match on that hash — `renderer/inventory.js` (`_productKeyHash`, `_filamentStockCount`, `_listRowFor`, `_productAsRow`, `_productDisplayRow`, catalogue preview)
- Inventory search now finds what the catalogue finds (issue #43): one shared word-based search — every word of the query must appear somewhere among brand, series, product name, material, aspects, colour, note, SKU / EAN, UID, tags and capacity — instead of the whole phrase inside a single field ("Bambu PETG HF" found nothing). Same tokenizer for the inventory, the Products views and the catalogue; the exact-code (SKU / EAN / UID) shortcut is unchanged — `renderer/inventory.js` (`_searchTokens`, `_hayHasAll`, `_rowSearchHay`, `_rowMatchesSearch`, `_filteredProducts`, `_catalogFilter`)
- Inventory grid cards read exactly like catalogue cards: title = the product name ("PETG HF - Blue" — the catalogue's own title for a catalogue spool, else "<series> - <colour>", else the colour) and sub-line "Bambu Lab · PETG" (`spoolCardTitle`, `spoolCardSub`); the table and the grouped spools show the material with its series ("PETG HF" + aspect, `materialWithSeriesAspect`); spools created before the series was stored fall back to the colour / bare material — `renderer/inventory.js`
- Printer board: dropping a printer group onto another no longer pushes the other printer's widgets down (and saves it); only objects the layout places itself are settled across machines (PR #40 by @Ptitlouis6012; follow-up issue #42) — `renderer/inventory.js` (`_planSettleColumns`)
