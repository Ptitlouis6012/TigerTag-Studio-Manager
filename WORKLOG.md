# Worklog — v2.18.0 (in progress)

## Added
- **Portable Windows build — no installation, runs from a USB key or an external drive.** For machines where installing software is not allowed. A second Windows target (`portable`) produces `Tiger-Studio-Manager-<version>-portable.exe` alongside the installer; it unpacks to a stable folder rather than a fresh random temp dir on every launch. Crucially the app also **keeps its data on the stick**: when electron-builder sets `PORTABLE_EXECUTABLE_DIR`, `main.js` redirects `userData`, `sessionData` and `logs` into `TigerStudioData/` next to the .exe — otherwise a "portable" build would still write accounts, cache and logs to `%APPDATA%` on the host, leaving a signed-in session behind on a shared PC and losing the inventory from one computer to the next. A read-only or locked folder falls back to the default location instead of refusing to start. macOS and Linux already had an equivalent (the `.zip` holding the `.app`, and the `.AppImage`). The CI needed no change — its signing filter and upload globs already match every `dist/*.exe` — `package.json`, `main.js`.

- **Dark mode.** Dark is the shipped default; Light is chosen in *Edit profile → Theme*. Verified in the real app in both themes on the inventory, the profile card and the login screen. **Known remainder, deliberately shipped:** ~270 raw colours still sit in a long tail of one-off rules, the 90 hex literals in `inventory.js` are untouched, the accent fill/text split is not done (white on a filled accent measures 2.1–3.9, under AA 4.5 — partly inherited: white on brand orange was already 2.61 before this work), and the printer / rack / friends screens were never reviewed in LIGHT theme. Dark being the default contains the exposure.
  - **The switch** — a Dark/Light segmented control in the edit-profile card (`#eacThemeSeg`), auto-saving like the language pref. Persistence is deliberately three-tier: `localStorage` (`tigertag.theme`) is the boot-time read source so the choice survives a cold, offline start; `users/{uid}.studioTheme` carries it across devices, on the user doc beside `vatCountry` and `priceInputMode` (`prefs/app` is the CROSS-APP doc shared with the mobile app, which is why `lang` lives there and the theme does not); and `users/{uid}/telemetry/studio.theme` records it as *usage* so the Hub can report the dark/light split. Prefs is what the app reads back, telemetry is what we aggregate — same value, two different jobs. It also rides along with `syncUserDoc`'s existing read instead of costing a second document fetch. `data-theme` is written statically on `<html>` so the palette is correct at first paint, and an IPC channel (`app:native-theme`) keeps the window chrome in step — otherwise Light leaves a black title bar over a white UI — `renderer/inventory.html`, `renderer/inventory.js`, `preload.js`, `main.js`.
  - **Token layer** — `:root` grew from 12 colour variables to ~75 semantic tokens, plus the `:root[data-theme="dark"]` override. Four groups: surfaces/text/borders (invert), brand+semantic accents (hue constant, `-soft` tints recomputed with `color-mix()` against `--surface`), fixed-polarity (`--on-accent` stays white on filled buttons in both themes), and always-dark (tooltips, media, the Add-Product panel that mirrors the mobile app). Adds an **ink ladder** (`--ink-04`…`--ink-85`) whose polarity flips with the theme, replacing ~450 hand-written `rgba(255,255,255,x)` / `rgba(0,0,0,x)` alphas — `renderer/css/00-base.css`.
  - **CSS sweep** — 1 297 of 1 567 raw colours across 17 stylesheets now resolve through tokens. Brand alphas became `color-mix()` on their token so they re-tint when the theme lifts a hue; solid semantic hexes map to tokens; `#fff` was resolved per-rule by reading the block's own background, which is the only way to tell a white *card* from a white *label on an orange button*. Shadows (163) and third-party brand colours (Discord, GitHub, MakerWorld, Shopify, the social-share buttons) stay literal on purpose — `renderer/css/*.css`, `renderer/IoT/*/*.css`, `renderer/printers/*/*.css`, `renderer/rfid_protocol/tigertag/modal.css`.
  - **Design decisions** — the sidebar and the TD1S panel follow the theme rather than staying black in a light UI (they are panels in the app, not instruments); camera/video surfaces and tooltips stay dark in both themes; the Add-Product panel stays dark on purpose (it mirrors the Flutter app's product screen) and so uses fixed white alphas rather than the ink ladder; the four Discord-style dark modals became themed floating surfaces.
  - **`scripts/check-theme-tokens.mjs`** (`npm run theme:check`) — guards the whole thing: fails on any raw colour or any `var(--x)` naming an undeclared variable, and reports the shadow/brand exemptions rather than hiding them.
  - **Open issue — accent fills vs accent text.** Measured contrast: white on a filled accent is 2.1–3.9 in both themes, under AA 4.5. Partly inherited (white on brand orange was already 2.61 before this work), partly made worse in dark by lifting the accents so they read as *text* on a dark ground. One token cannot be both a legible fill under white text and a legible label on a dark surface. The fix is a `--X` (fill) / `--X-text` (label/icon) split, applied mechanically since the sweep already distinguishes `background:` from `color:`. Not done yet.
  - **Backend** — `theme` added to the `telemetry` field whitelist in `firestore.rules` (**`TigerTag_Firebase_Backend`**) and **deployed** to `tigertag-connect`. That collection rejects unlisted fields *silently*, so before the deploy the telemetry write vanished with no error at all. Committed as `0d85733` on `main` in the backend repo, so the deployed rules and the repository agree.

## Changed
- **Edit profile is now a side card sliding in from the left, and its interface was rebuilt.** The account lives in the left sidebar, so its editor unfolds from the side you clicked instead of jumping to the middle of the screen. It reuses the existing side-panel idiom (fixed, 8 px inset top/bottom, rounded on the inner edge, slide on `transform`) mirrored horizontally. The overlay keeps its id and its `.open` class, so the open/close code was untouched — only the geometry moved.
  - **New information architecture.** Eleven stacked fields became a pinned title bar + identity hero + five scannable sections — *Profile*, *Links*, *Appearance*, *Language & region*, *Advanced* (admin-only) — separated by hairlines instead of stacked margins. One row per setting: label left, control right, so the eye runs down a single column of values instead of zig-zagging past full-width fields. Header and hero stay pinned while the body scrolls; sign out is pinned in a footer rather than hiding at the end of the scroll. **Nothing was removed** — every control, hint and id is still there.
  - **Its own stylesheet block.** The card's look is now defined end to end in one delimited section of `60-modals.css` scoped to `#editAccountModalOverlay`, instead of patching the inherited centred-modal rules property by property. Section headers dropped shouted uppercase for sentence case, 500 is the heaviest weight, and the admin badge became a tinted pill rather than a filled gradient — it states a status, it is not a button.
  - **Avatar colours moved with their avatar.** They paint the avatar's background, so they belong in the identity block, not in a settings section — and they went from two rows of seven to one row of thirteen, halving the height for the same reach. (Explicit width/height rather than `aspect-ratio`: inside a flex row the ratio loses to flex sizing and the circles stretch into ellipses.)
  - **The links block reads as a system now.** Each link is a bordered card carrying its auto-detected platform icon; the trailing empty row is dashed and transparent so it reads as the slot waiting to be filled. Added a line stating the links are visible to friends and on the public profile — `syncUserProfile` has always mirrored them, but nothing in the UI said so — `renderer/inventory.html`, `renderer/css/60-modals.css`.
  - **Enter commits a social link.** Pressing Enter in a link field now leaves the field, which is what the hand expects after typing a URL. It simply blurs: the existing focus-out path is the ONE save route, so calling the save directly as well would race it and re-render the editor under the cursor — `renderer/inventory.js`.
  - **Help text became an ⓘ bubble.** The paragraph under Country was replaced by a hover/focus tip reusing the app's shared `#toolInfoPop` — same component as the rack view's `.rp-info`, extended by one selector rather than copied a fourth time. The string is unchanged, it just stops occupying the card permanently: "France · 20% · €" already shows the rate; only the fact that the choice also picks the *currency* needs saying, and only to whoever asks — `renderer/inventory.html`, `renderer/inventory.js`, `renderer/css/60-modals.css`.
  - **The Dark/Light switch is a sliding pill.** 172×34 instead of 172×46 — the global `button { height: 40px }` rule applied here too and made it chunky. The pill is a single `::before` positioned by `:has()`, so the markup and the JS keep toggling `.active` and know nothing about it; `HT | TTC` inherits the same treatment for free.
  - **The two dropdowns are themed.** They reuse the existing `_enhanceSelect()` helper rather than a second implementation: a native `<select>` opens an OS list no CSS can reach, so it stayed light-on-light whatever the card was wearing. They also drop the orange `is-active` treatment inherited from the inventory filters — there it signals a live filter, here it signalled nothing and just shouted.

## Fixed
- **The ✕ on a social link emptied the field but left the row on screen.** `_saveSocials` only re-renders the editor once focus has left it — and the ✕ lives inside it — so the blanked row lingered, still showing its old platform icon and its own ✕, next to the empty add-row: two empty fields, and a delete that looked broken. The handler now removes the row outright (and merely resets the trailing add-row, which must always exist). Removing the node is also the surgical move: no `innerHTML` rebuild, so the other fields keep their caret and selection — `renderer/inventory.js`.
- **App-styled dropdowns were clipped when they opened near the bottom of a scroll box.** An absolutely-positioned popup cannot escape a scrolling ancestor, so in the profile card the Country list opened downward into `.eac-body`'s clip and half of it was cut away. `_enhanceSelect` already flipped horizontally against `#card-inv`; it now also flips vertically (`.csel-pop--up`) against the nearest ancestor that actually clips, found by walking up for a non-visible `overflow`. Every app-styled select benefits, not just this card — `renderer/inventory.js`, `renderer/css/70-detail-misc.css`.
- **Monochrome social logos vanished on a dark background.** X, TikTok and GitHub were pinned to `#111111` in `_SOCIAL_MAP`, so on the account and friend banners they rendered near-black on a near-black card — the icon was there, just invisible. These three brands have identities built to invert (black on white / white on black), so they now resolve to `var(--text)`: near-black in light, near-white in dark, which is what the brands do themselves. Every other entry is a genuinely chromatic brand colour and stays literal — Instagram pink is Instagram pink in any theme — `renderer/inventory.js`.
- **27 CSS variables were used but never declared** (`--fg`, `--bg-2`, `--surface2`, `--surface-hover`, `--accent`, `--ok`, `--hairline`…). Those with a fallback silently rendered the fallback — often a *dark* value in a light UI, i.e. rules written for a theme that did not exist. Those without one (`color: var(--fg)`, `background: var(--bg-2)` ×5, `var(--surface2)` ×3, `var(--surface-hover)`) were simply invalid, so the element had no background or colour at all. All 27 now resolve to canonical tokens — `renderer/css/*.css`, `renderer/IoT/*/*.css`.
- Stray extra parenthesis in `color: var(--muted));` made the TigerScale WebSocket log text fall back to the inherited colour — `renderer/IoT/tigerscale/tigerscale.css`.
- 101 dead `var(--token, fallback)` fallbacks removed: the variables always resolved, so the fallbacks were unreachable code that also mis-stated the intended colour — `renderer/css/*.css`.

## Removed
- The "Type prices this way — we always store them tax-free…" hint under the price control in the profile card. `Prices` over an `HT | TTC` choice cannot mean anything else, so the sentence only added weight — `renderer/inventory.html`, i18n key `priceInputHint` (9 locales).
