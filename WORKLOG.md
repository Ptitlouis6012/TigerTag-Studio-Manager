## Fixed
- Elegoo Centauri Carbon 1 camera never showed ("camera connection failed"): the printer answers Cmd 386 with a scheme-less `VideoUrl` (`<ip>:3031/video`, seen on V1.4.49), which an `<img>` resolved as an app-relative path; `sdcpVideoUrl()` adds `http://`, swaps an empty / 0.0.0.0 / loopback host for the address the printer was reached on, refuses non-http(s), and keeps the default URL when nothing usable is left — `renderer/printers/elegoo/sdcp.js`, `PROTOCOL.md` (PR #82, Ptitlouis6012)
- Elegoo camera widget showed FlashForge's "only one viewer is allowed at a time" on any load error (a CC1 takes 4 streams) and FlashForge's alt text; it now has its own `elgCamFailMsg` / `elgCameraAlt` — `renderer/printers/elegoo/widget_camera.js` (PR #83, Ptitlouis6012)
- USB scale (DYMO M-series) lost after its auto-sleep until unplugged/replugged (issues #74, #76): on some machines the scale powers off without leaving the USB bus, so the open handle stayed silent with no error and the woken scale was never reopened; a scale is now announced connected only on its first real frame, and 5 s of silence closes the handle and resumes polling — `main.js`
- Add-printer flow left open on top of other side cards: with the brand picker or a brand's choice/scan/manual card open, opening a printer, a spool, a group, the debug panel or the Firestore explorer (or Friends / notifications) put the new card underneath; the flow now closes first — `_closeAddPrinterFlow()` in `renderer/inventory.js` (also in `_closeAllSidePanels`)
- TigerData+ creation counter (`cloudPlusAddedTotal`) never reached Firestore: the telemetry rules' field whitelist did not list it, so every such write was refused silently; whitelisted together with the new `certifiedAddedTotal` — backend `firestore.rules` (deploy needed)
- Printer side card: scrolling could slide the whole panel up and cut its header in half — the off-screen Snapmaker file sheet made the `overflow: hidden` panel scrollable by script/anchoring; detail panels now use `overflow: clip` — `70-detail-misc.css`
- Bambu Lab camera (JPEG A1/P1 and RTSP X1/H2) could run two reconnect loops for the same printer — a retry waiting on its timer survived a stop or a new start, and the two kept kicking each other off a printer that serves one camera client; a per-key generation now ends a stale loop — `main.js`
- Printer modules' error toasts never showed: the printers context called `toast(msg, type)` against a `toast(el, kind, msg)` signature, so every brand's error message (13 call sites) was silently dropped; it now goes through the app's flash message — `renderer/inventory.js`
