# Worklog — v2.17.2 (in progress)

## Added
- **Product card: HEX colour, quantity, and a raw-JSON block in debug mode.** DÉTAILS gained a **Color** row listing every slot as `#RRGGBB`, one per line, alpha normalised to `RRGGBBAA` (a dual/tri product shows all of them, not just the first) and a **Quantity** row showing the product's own `measure` with its unit — `2 kg`, not the `2000 g` the gauge uses. With debug mode on, the card now ends with the same collapsible **raw JSON** block (and copy button) the material side-card has, so a catalogue product's seed can be inspected without leaving the card — `renderer/inventory.js`.

## Fixed
- **The Refill / Recycled / Filled badges were never displayed anywhere.** The spool detail card computed `infoBadges` and built `infoHtml2` from them, then never inserted it into its template — dead code, which is why a "PLA Basic Refill" spool showed no badge at all (eslint had been flagging the unused variable). Inserted it into the Details body, and added the same three chips to the **product card** (same `.aspect-chip` markup and the same existing `badgeRefill`/`badgeRecycled`/`badgeFilled` keys, already translated in all 9 locales — no new key, no new CSS). They read `info1`/`info2`/`info3` through `normalizeRow` (`isRefill`/`isRecycled`/`isFilled`) — `renderer/inventory.js`.
- **Side-card detail rows: a long value ran off the edge, and a medium one wrapped with half the row empty.** `.panel-row .pv` was capped at `max-width: 60%`, so a SKU broke onto two lines even when the label beside it was short and the space was free; and nothing could break an UNBREAKABLE string (a SKU or barcode has no spaces), so a really long one overflowed past the right edge. The label is now `flex: 0 0 auto` and the value `flex: 1 1 auto; min-width: 0` — it takes all the free space and only wraps when it genuinely has to — plus `overflow-wrap: anywhere` for the no-space case. Applies to every panel row, so the material card benefits too — `renderer/css/70-detail-misc.css`.
- **Catalogue seed: `measure_value` and `grams` are two different quantities and were read into one variable.** `_catalogDocFromApi` did `Number(fil.measure_value ?? fil.grams)` and then ran the result through the unit conversion — but `measure_value` is unitless and only means something with `measure_unit` (500 + "g", or 2 + "kg", or a volume), while `grams` is ALREADY normalised by the API. A missing `measure_value` on a kg product would therefore have yielded 2000 x 1000 g. `grams` is now the authority for `measure_gr`, and the raw `measure_value` (paired with `id_unit`) is kept for the chip payload as the `.ttag` contract requires; conversion only runs when the API omits `grams`. Verified on four live products, including the failing path — `renderer/inventory.js`.
- **The product card always showed a 1 kg spool, whatever the real size.** `_renderProductCard` hardcoded `const cap = 1000, curW = 1000`, so a 500 g, 750 g or 2 kg product all read "1000 g / 1 kg total" with a full bar — while the grid card right next to it showed the correct `500 g`. The capacity was never missing: the catalogue seed already carries it (`_catalogDocFromApi` sets `measure`/`measure_gr` from the API `measure_value`+`measure_unit`, falling back to `grams`), and `normalizeRow` exposes it as `r.capacity`. The card now uses it, falling back to parsing the catalogue item's display string (`"500 g"` / `"2 kg"`, new `_catMeasureToGrams`) for a preview opened before the API detail lands, then to 1 kg. The spool still renders FULL — a product identity has no per-spool weight — only its capacity is now real. **One render function serves all six product-card entry points** (catalogue, favourites, lists, cart, friend view, groups), so every card in the app was affected and is fixed by this. Verified against the live API: 500 g -> 500, 2 kg -> 2000, 750 g -> 750 — `renderer/inventory.js`.
