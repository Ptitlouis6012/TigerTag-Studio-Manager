# Worklog — v2.22.1 (in progress)

## Added
- A **Refill** entry at the top of the container picker (type *Without MasterSpool*), for a spool stored with no masterspool at all — a generic container weighing nothing, so the net weight is the spool's own. Illustrated by a bare refill coil rather than a crossed-out spool: every other row shows the object you have, and without a masterspool the object is the filament itself, wound and self-supporting. It is shown uncoloured, because a coil's colour is the filament's and not the container's — any real colour would be wrong for most spools, and the two rows beside it show a container's own colour. Cut out to a transparent 256×256 like the rest of the catalogue, so it sits on the picker's tile in either theme. Contributed by [@Ptitlouis6012](https://github.com/Ptitlouis6012) (#17) — `data/container_spool/spools_filament.json`, `assets/img/spool_filament/oem_no_masterspool.png`

## Changed
- The TigerScale card's **Tare is now a key beneath the screen**, inside the card, instead of a separate button floating under it: it is where the button sits on the scale itself, and it wears the firmware's own tones and its two-line face — the fixed `0.0` above the word, exactly as the device prints it — so it reads as part of the machine rather than a control the app parked nearby. The `0.0` is part of the key's face, not a reading: the scale shows it fixed too, and the comment beside it says which span to wire should the firmware ever broadcast a real offset. The card's frame moved out of the live block to make room for it — the button stays a sibling of that block rather than a child, because the block is replaced wholesale on every WebSocket frame and a hold in progress would be cancelled ten times a second. Disconnecting now hides the whole card, Tare included, rather than leaving an empty bordered box with a dead button in it — `renderer/IoT/tigerscale/index.js`, `renderer/IoT/tigerscale/tigerscale.css`
- **The TigerScale live card now mirrors the scale's own weigh screen** — weight and divider on the left, container and filament values with the spool's rack location on the right, tare below, on a dark inner panel using the firmware's own palette so a status badge reads the same on both screens. The rack location is real Firestore data in the detail panel's coordinate format, not a placeholder; the hand-rolled cellular-bars WiFi indicator gives way to the app's own glyph; and the redundant "last known spool" row goes, superseded by the block's own brand and material display. Contributed by [@Ptitlouis6012](https://github.com/Ptitlouis6012) (#16) — `renderer/IoT/tigerscale/index.js`, `renderer/IoT/tigerscale/tigerscale.css`

## Fixed
- **Every Creality CFS slot came out grey on the printer board** while the machine's own panel showed the right colours. Creality broadcasts a colour as bare hex with no `#`, sometimes with a stray leading zero (`0FF5722`) — neither is a CSS colour. The parser that fixes that was defined INSIDE the panel's own render function, so the board's feeds, written later, read the raw payload and published a value no stylesheet could interpret. The parser is now module-scope and both feeds use it: one parser, every consumer. Creality was the only brand whose board feed read the raw payload rather than the driver's already-normalised state — the others were checked. Reported by a user — `renderer/printers/creality/index.js`
- Choosing a filament colour on a Bambu Lab machine changed nothing on screen until the printer's next report. The optimistic local update wrote the WIRE shape into the INTERNAL one: the external tray kept the unparsed 8-hex string, and the AMS branch set a `tray_color` field nothing downstream reads. Found while checking whether the Creality defect had siblings — `renderer/printers/bambulab/index.js`
- The TigerScale's name was invisible in light theme: it sits on the card's shell, which follows the theme, but was painted a hardcoded white meant for the firmware's dark inner screen — `renderer/IoT/tigerscale/tigerscale.css`
- The Tare button's hold fill could not be seen in light theme: it was painted `--ink-40`, which flips to a dark ink there, over a key that keeps the firmware's dark tone in both themes — an invisible fill reads as a broken button, since nothing happens until the hold completes — `renderer/IoT/tigerscale/tigerscale.css`
- Switching language left an open Scales panel in the previous one. Its cards are built once and only patched surgically afterwards, so nothing ever revisited their text — the panel is rebuilt with the rest of the reactive chain now. Contributed by [@Ptitlouis6012](https://github.com/Ptitlouis6012) (#16) — `renderer/inventory.js`
