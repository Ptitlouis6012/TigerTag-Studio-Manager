# Worklog — v2.36.0

## Added
- **Bug or idea? — in-app report → public GitHub issue.** A sidebar button **Improvements & suggestions** (quiet brand-orange outline, three-sparkles (AI-style) glyph, under Buy me a coffee; lit while the card is open or a request is in progress — same rule as its tab) toggles a **left side card** that slides out from behind the sidebar with the same motion as the right-hand cards (.25s translate, mirrored; it moves inside a click-through clipping window `.rep-clip` whose left edge is the sidebar's, «-tab to close) — not a modal: the app stays usable and the draft (text, screenshots, choices) survives close / reopen until it is sent, so you can navigate and snap several screens. While the card is open, a file dragged from the desktop is an attachment wherever it is dropped in the window — the window-wide `.ttag` import drop zone stands down (it used to swallow the drop) and the card shows a full "Drop to attach" overlay for as long as files hover the window; at rest the attachments sit in a dashed drop zone ("Attachments n/5" + drag / paste hint). A **‹ Back** link above the form returns to the kind picker, keeping what was typed. Once a topic is picked the request is *in progress*: closing the card leaves its tab parked on the sidebar edge as **»** (a short nudge, "Back to my request") so it reads as still there — go snap another screen, click » to come back; the tab goes away only after sending or going back to the topic list (abandoned). The tab now lives in `<body>`, positioned with the card (`_syncTab`, `_pinToSidebar`). A **Cancel** button, left of Send, drops the request (draft cleared, card closed, no parked tab). **My requests** tab next to *New request*: every request of the account with its kind, title, `#issue`, age, reply count and status — Sent / In progress (GitHub label `in progress`) / Done (closed completed) / Not planned (closed not planned) / Closed by you — a GitHub link, and **close my own request** (two-step ✕ → *Close it?*; comments "Closed by the reporter…" and closes the issue as not planned). Statuses are read from GitHub on demand by the new `myReports` function (backend: `list` = query `bugReports` by uid + fetch each issue, `close` = owner-checked PATCH) at sign-in (+8 s) and when the tab opens — no webhook; a change since the last look writes a `request_status` notification (`data: { reportId, number, status, title }`) that the notification centre words in the user's language (`notifReq_*`) and opens *My requests* on click; reports from before statuses existed are recorded silently. A **Buy me a coffee** block ("want it to go faster? a few coffees = less sleep, faster code") sits under the kind picker and, bigger with its own yellow button, on the thank-you screen — same link as the sidebar coffee button. It opens on a **kind picker** first, like Zonara's requests — Problem / Improvement / New idea / Question / **Catalogue correction** (pick the material with the catalogue search — same index and words as the Catalogue view, exact barcode / SKU / id first — then say what's wrong; the issue carries the product's link, id, brand, material, SKU, EAN) / **New brand** (name + website, validated, to verify it), each with an icon, an accent colour and a one-line hint (labels `bug` / `enhancement` / `idea` / `question` on GitHub; a chip above the form shows the choice, click to change) — then the form, whose placeholders follow the kind. The form holds: bug / idea, a one-line title, details, up to 5 attachments — screenshots, images or **PDFs** (≤ 5 MB, max 2, checked for `%PDF` server-side, linked under *Attached documents*) — (**Snap the app** = `webContents.capturePage()` with the card hidden, opening the annotator on it straight away, paste, drop or file; each re-encoded to JPEG ≤ 1920 px) with a full-screen **screenshot editor** (`renderer/report/annotator.js`, at least Zonara's, plus more): every mark stays an object until Done — select / move, resize by handles, recolour / resize, delete, duplicate; tools move, pen (smoothed), eraser (cuts pen strokes, removes other objects), arrow, line, box, circle (⇧ = square / circle, 45° snap for lines), highlighter, text (inline box, Enter, double-click to edit, contrasting halo), numbered steps (1, 2, 3… auto), and **blur** (pixelates an area — for anything private, the report being public); 7 colours, S/M/L/XL, undo / redo (80), keyboard shortcuts (V P E A L R O H T N B, 1-7, ⌘Z / ⇧⌘Z, ⌫, ⌘D, arrows to nudge) and a contextual tip line; drawn in image pixels, exported as JPEG, the metadata that travels with it shown up front (app version, OS, view, language, printer brands — never an id or credential), an opt-in to attach the recent error log, and a mandatory **public** checkbox ("this will be public on GitHub, nothing private in it"). Sent to the new `reportIssue` function (backend, deployed) with the ID token in `X-Firebase-Id-Token` — not `Authorization`, which Cloud Run inspects itself and once refused with a 401 — retried once with a forced token refresh; the metadata is refreshed at send time, which rate-limits (5 / account / 24 h), re-encodes the images (sharp, EXIF dropped) into Storage `bugReports/{id}/n.jpg` with download tokens, opens the issue on TigerTag-Studio-Manager (kind label + `from-app`, title tagged `[Bug]` / `[Improvement]` / `[Idea]` / `[Question]`, no uid / name / email in it) and keeps the private trace in `bugReports/{id}` (uid, issue number). The dialog then shows "report #N is in" with a link to the issue. Supersedes PR #44 — `renderer/report/{index.js,report.css}` (new), `renderer/inventory.{js,html}`, `main.js` (`report:capture`, `app:info.systemVersion`), `preload.js` (`captureWindow`), `renderer/css/{00-base,10-settings,70-detail-misc}.css`, 13 new icons (`suggestion`, `camera`, `arrow-up-right`, `square`, `highlighter`, `undo`, `redo`, `eraser`, `line`, `circle`, `type`, `step-number`, `blur`); backend `functions/reportIssue.js` (secret `GITHUB_ISSUES_TOKEN`)
