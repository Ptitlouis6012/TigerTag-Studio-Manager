# Worklog — v2.30.0

## Added
- Grid cards: a name too long for its card scrolls into view the moment the card is hovered (straight out to its end, a pause, back, looping); ellipsised again when the pointer leaves. Honours reduced-motion — `renderer/inventory.js`, `renderer/css/70-detail-misc.css`
- Anycubic cloud printers: the doc (`users/{uid}/printers/anycubic/devices/cloud_<id>`) now also carries Anycubic's shared cloud-MQTT TLS identity — `acuCloudCaDerB64`, `acuCloudClientCertPem`, `acuCloudClientKeyPem` — so a TigerSpool can dial `mqtt-universe.anycubic.com:8883` itself with what it reads there. Served by a new `anycubic:cloud-certs` IPC from `services/anycubicCloudCerts.js`; written on add, on every token refresh, and once per session as a catch-up for older cloud docs. Never on LAN docs, never logged — `main.js`, `preload.js`, `renderer/inventory.js`, `docs/anycubic-send-to-printer.md`
- FlashForge Creator 5 / 5 Pro: the official "Cloud + LAN" firmware FlashForge built with TigerTag, surfaced in the app. New public repo `TigerTag-Project/FlashForge-TigerTag-Creator5-Firmware-Lan-and-Cloud` (one GitHub Release per version, `Creator5-<v>.tgz` + `Creator5Pro-<v>.tgz`). Resolver `renderer/printers/flashforge/creator5-fw.js` (GitHub `releases/latest`, 24 h cache + ETag, build-time fallback, per-model asset pick, `X.Y.Z-A.B.C` version compare). The printer's Info window gains a firmware block on a Creator 5 (up to date / update available, "Download <version>" for THIS model, "How to install" → the repo's USB walkthrough, and a warning to skip the printer's own OTA update); a local notification (same later / ✕ contract as the Paxx one) fires when a connected Creator 5 runs an older version — `renderer/printers/flashforge/{creator5-fw.js,index.js}`, `renderer/inventory.js`, `renderer/css/50-snapmaker.css`

## Changed
- LAN scan: the add button reads just "Add" (was "Add these N printers") — `renderer/printers/scan-pick.js`
- Photos are held back while the results move — during a drag of the colour-filter window, and for 1 s after the last wheel notch on it or the last scroll of a results list (each restarts the second): every view shows only the colours meanwhile, the images keep loading unseen and appear already loaded — no more photos flickering in on every move — `renderer/inventory.js`, `renderer/css/70-detail-misc.css`
- Product card: one identity block — brand · material, the name, then a single chip row with aspects 1-2, the refill / recycled / filled data (info1-3) and the weight (capacity, e.g. "1000 g"). The separate Aspect and Weight sections are gone, and with them the always-full fill bar, its scale and the redundant "1 kg total" — `renderer/inventory.js`
- Spool detail card: the master-spool (container) section now sits above the weight section — it sets the tare the weight is read against — `renderer/inventory.js`
- Master spool (container): the "change master spool" and "edit its weight" buttons on the spool card, and the weight pencil in the container picker, are always visible in grey and brighten on hover (they only appeared on hover) — `renderer/css/70-detail-misc.css`
- Material swatch: a bicolor (any two hard-edged colours — chip aspect or catalogue list) is now split on the 135° DIAGONAL, first colour top-left, instead of vertically; 3+ colours stay a camembert. Follows the ecosystem convention, amended to v1.1 first in TigerSystem-Docs (`material-swatch.md` + reference renderer + French translation). One change in `_pieSplit`, so every surface follows (swatches, frames round photos, Add-Product preview) — `renderer/inventory.js`, `playground/material-swatch/index.html`, `docs/MATERIAL-SWATCH.md`
- Colour dots removed where the colour frame now says it: grid card names, grouped-spools names, the product-info header, and the big circle of the spool detail / product cards. That section is titled "Aspect" (was "Colour(s) & Aspect"); on a TigerData spool the colour editor, which the circle used to open, is now a "Change colour" chip beside the aspect chips. Table colour columns unchanged — `renderer/inventory.js`, `renderer/css/70-detail-misc.css`
- Spool photos are framed in the spool's colour everywhere they show — grid cards, product card, spool detail card, grouped spools, inventory / favorites lists, wishlist rows and the catalogue list, and the product-info (reorder) header: the photo is inset so the spool's colour shows round it as a frame (rounded photo corners) — `renderer/css/70-detail-misc.css`
- FlashForge add form (#29): the "Password" field is labelled **Printer ID** — the name the printer's own screen and the connection tutorial use; its hint and the IP/serial hints point at the tutorial's paths ("Basic Info" / gear → "Network Mode", not About → Network or FlashPrint), and the helper says a scanned printer needs only the Printer ID. Field key stays `password` (no data change) — `renderer/printers/flashforge/settings.js`
- Snapmaker Paxx firmware: offline fallback bumped to `v1.6.0-paxx12-22` (the live resolver already served it; #21) — `renderer/printers/snapmaker/paxx.js`
