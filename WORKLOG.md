too long → `ndef-too-long`. **Sized to the chip**: the NDEF room is read from the chip's capability container (page 3, byte 2 × 8 — 144 NTAG213, 496 NTAG215, 872 NTAG216; `_ndefCapacity`, `rfid:ndef-capacity`, preload `ndefCapacity`), the counter shows "bytes / room of the smallest chip on the readers" (`ndefRoom`, `paintCounter`), each chip is checked on write; Links (the Link type and a contact's website) are checked and may use any scheme — a camera / data stream (rtsp://, rtmp://, ws://, mqtt://…), a share (smb://, ftp://), an app link (spotify:…): without a scheme "tigersystem.io" becomes https://tigersystem.io and a bare local address (192.168.0.1, localhost, with or without a port) http://; a "scheme://" link needs a real host checked as typed (a domain with a 2+ letter TLD or punycode, an IPv4 ≤ 255, IPv6, localhost, a .local name — "1.2.3" refused although the URL parser completes it), a port ≤ 65535, a login allowed (cameras), no space; javascript:, data:, file:, vbscript:, about:, blob: refused (`normUrl`, `validHost`, `validUrl`, `URL_FIELDS`); an invalid one frames its field red as it is typed (`markUrl`, `.is-invalid`, `aria-invalid`) and blocks the write and Auto (`nfcNdefBadUrl`). ## Fixed

- **The new-chip card ("What would you like to do?") is no longer interrupted by scans** (`renderer/inventory.js`: `_chipCardUp` in `onRfidTagScanned`, `onRfid`, `onRfidForeignChip` and at the top of `_processNfcScans` for a scan buffered just before it opened; `docs/LINKED-CHIPS.md`): while it is up a chip placed on the TigerPOD opens no spool, creates or updates none, and no longer reopens the card on another view (the old "blank chip refreshes the chooser" branch is gone) — an old spool used to pop into the inventory while working in the card. Placing / removing a chip still updates the card (greyed Link, NFC tools plates).

- **An NDEF tag no longer comes in as a made-up spool** (`renderer/inventory.js`, `_processNfcScans`): a chip is taken for a spool only when its `id_tigertag` is a TigerTag version of `id_version.json` (not "RFID Empty", not "TigerTag Init"). A tag written by a phone or by the NFC tools (a link, Wi‑Fi…) parses as noise with non-zero material and brand ids, and was created as a spool when placed on the TigerPOD.

- **Eleven messages called `toast()` with the wrong arguments** (`toast(msg, "success")` instead of `toast(el, kind, msg)`), so each one threw `Cannot create property 'innerHTML' on string …` — the "API refresh failed" seen in issue #154's report, and the TigerTag → TigerTag+ upgrade, which wrote the spool then stopped before closing its cards and opening the chip rewrite. - **FlashForge "wrong serial number" names its real cause** (issue #86): a printer not in LAN mode answers `SN is different` whatever the serial, so `ffgErrSnMismatch` now says to turn on LAN mode on the printer (required, also with the Cloud + LAN firmware) before checking the serial; `renderer/printers/flashforge/PROTOCOL.md` notes it. Files: `renderer/locales/*.json`, `renderer/printers/flashforge/PROTOCOL.md`. i18n: `ffgErrSnMismatch` reworded (11 locales).

- **USB scale after a computer sleep** (issue #138, Windows, not reproduced: on macOS an M5 keeps reporting zero frames while switched off and resumes on wake): on system resume (`powerMonitor` `resume`) the scale handle is dropped and the scale opened afresh; a handle closed after `SCALE_SILENCE_MS` of silence is now logged (`[Scale] No frame for 5 s …`), so a report's `main.log` shows which case it hit; the log-location comment in `main.js` names the real folder (`tigertag-inventory`, not "Tiger Studio Manager"). Files: `main.js`.

- **Bambu RTSPS camera recording** (PR #152 by @Ptitlouis6012, merged with review fixes): a recording taps the stream main already reads for the picture (`cam:rec-tap-start`, `_camLive` / `_camTaps`, MJPEG frames into a .mov) instead of opening a second connection the printer cut after ~10 s; the live view dates pictures on arrival (`-use_wallclock_as_timestamps 1`) so a camera clock jump no longer makes `fps=30` flood the main process (measured on Windows with a P2S — never seen on macOS, an X1C is fine there).
